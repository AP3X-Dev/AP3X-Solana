**Source PRP:** `roadmap/02.5-pumpfun-protocol.md`
**Author:** CJ (advisor-approved during autonomous run `autonomous-prp-02.5-2026-04-20`)
**Status:** approved_with_notes (advisor)
**Builds on:** `docs/superpowers/specs/2026-04-19-prp-02-solana-runtime-design.md` (runtime), `docs/superpowers/specs/2026-04-19-prp-01-solana-substrate-design.md` (substrate)

## 1. Goal restatement

Ship the first Solana vertical — pump.fun — as two new packages on top of the shipped substrate + runtime:

- `@ap3x/pumpfun-events` — program ID constants + decoders for both pump.fun programs (bonding curve + PumpSwap AMM), registered into the substrate's `EventDecoderRegistry`
- `@ap3x/pumpfun-protocol` — typed read-only on-chain client, bonding curve + AMM math, **pure instruction builders** (`buildCreate`, `buildBuy`, `buildSell`, `buildPumpSwapSwap`), unified routing across the graduation boundary

Plus `examples/pumpfun-watch/` — live mainnet dogfood mirroring the `examples/spl-watcher/` pattern from PRP-02.

After PRP-02.5, a developer can: decode every pump.fun on-chain event variant, query any mint's state (curve or post-graduation pool), compute fair prices on either side of the graduation boundary, and **construct any pump.fun instruction ready to be signed and submitted**. PRP-03 wraps these builders with the write-path safety layer (simulate, receipts, policy, Jito bundle dispatcher). PRP-02.5 stops there.

Deliberate non-goals:
- **No write-path safety.** Builders return raw `{ programId, accounts, data }`. Simulation, receipt-gating, policy tiers, circuit breakers, and Jito dispatch ship in PRP-03.
- **No off-chain HTTP APIs.** `advanced-api-v2.pump.fun` + `frontend-api-v3.pump.fun` re-homed to PRP-04's signal layer.
- **No authority revocation, metadata updates, vanity grinding, launch-and-snipe orchestration, airdrops.** Those ship in PRP-03.5 alongside their policy-tier gating.
- **No stateful streaming inside the protocol package.** Live pump.fun event streams are the runtime's `SignalQueue` responsibility.

- `pumpfun-events` imports from substrate only.

- The example wires everything together: consumes `@ap3x/solana-signals` + `@ap3x/solana-strategy` for live streaming and `@ap3x/pumpfun-events` + `@ap3x/pumpfun-protocol` for program-specific logic.

### 3.2 `@ap3x/pumpfun-events` structure

```
src/
├─ program-ids.ts             # PUMPFUN_BONDING_CURVE_PROGRAM_ID, PUMPFUN_PUMPSWAP_PROGRAM_ID
├─ bonding-curve/
│   ├─ event-types.ts         # PumpFunBondingCurveEvent discriminated union
│   │                         # variants: Create | Trade | Complete | SetParams | CreatorFee | Migrate
│   ├─ discriminator.ts       # maps log-line signatures → variant kind
│   └─ decoder.ts             # ProgramDecoder<PumpFunBondingCurveEvent>
├─ pumpswap/
│   ├─ event-types.ts         # PumpSwapEvent discriminated union
│   │                         # variants: Swap | AddLiquidity | RemoveLiquidity | Admin
│   ├─ discriminator.ts
│   └─ decoder.ts             # ProgramDecoder<PumpSwapEvent>
├─ borsh-helpers.ts            # shared Borsh primitives reused across both programs' decoders
└─ index.ts                    # re-exports: decoders, types, program IDs, borsh helpers
```

Each decoder is a stateless `(ProgramLogChunk) → Event | UnknownEventDecode` function. The decoder matches on the first `Program <programId> invoke` discriminator in the chunk, dispatches via the variant discriminator table, and calls a Borsh-shaped decoder for that variant's payload. Unknown variants → `UnknownEventDecode { kind: 'unknown', programId, reason }` with a structured `reason` that separates cosmetic drift (`unknown-discriminator`) from real breakage (`truncated-data`, `borsh-parse-error:<field>`).

### 3.4 Key architectural decisions

**Stateless protocol package.** `@ap3x/pumpfun-protocol` has no lifecycle — no `start()`, no `stop()`, no background tasks, no in-memory stream buffers. Every method is one-shot request → response. Live streaming is the runtime's `SignalQueue` responsibility; callers wanting live pump.fun trades subscribe to the queue filtering for `pumpfun.trade` / `pumpfun.swap` kinds. This keeps testing trivial (no lifecycle ceremony), composition easy (drop into any script/agent/backend), and avoids the "two ways to get recent trades" design smell.

**Pure instruction builders live here.** Every substrate package that has instructions ships them as pure functions (`@ap3x/solana-spl.buildTransferInstruction`, `@ap3x/solana-metaplex.buildUpdateMetadataInstruction`). Pump.fun matches this pattern. The builder signature is `(params: Params) → { programId, accounts, data }`; it does not sign, it does not submit, it does not simulate. Safety wraps the submit call and ships in PRP-03.

**Unified routing across the graduation boundary.** Callers wanting to trade a pump.fun token without knowing whether it's pre- or post-graduation use `routing.buy(mint, params)` — the helper fetches `curveState(mint)` and dispatches to `buildBuy` or `buildPumpSwapSwap` based on `complete`. Raw builders remain available for callers who already know which side of the boundary they're on.

**PumpSwap AMM math ships here, not later.** Post-graduation tokens live on PumpSwap, not on the bonding curve. Any strategy tracking a position across the graduation boundary needs AMM math to compute fair price and sizing post-grad. Deferring this would cripple strategies from day one.

**Real captured fixtures, no mocks.** Matches the user's stated preference (2026-04-20 feedback memory). Two fixture files: `pumpfun-per-variant.jsonl.gz` (~100 events, one real captured sample per variant — used by fast decode unit tests) and `pumpfun-lifecycle.jsonl.gz` (~500 events, 2-3 tokens traced Create → graduation → PumpSwap trades — used by integration tests that exercise the boundary). Both capture scripts are Helius-free-tier-compatible and self-skip gracefully without an API key (matches PRP-02's gate-8 fallback pattern).

**Program IDs live in the lower package (`pumpfun-events`).** Both packages need them; keeping them in the lower package avoids a circular dep. `pumpfun-protocol` re-exports for convenience.

## 4. Component specifications

### 4.1 `pumpfun-events` — decoders

**Bonding curve decoder** (`bonding-curve/decoder.ts`):

```ts
export const bondingCurveDecoder: ProgramDecoder<PumpFunBondingCurveEvent> = {
  programId: PUMPFUN_BONDING_CURVE_PROGRAM_ID,
  decode(chunk: ProgramLogChunk): PumpFunBondingCurveEvent | UnknownEventDecode {
    const discriminatorLine = findInvokeLine(chunk);
    if (!discriminatorLine) {
      return { kind: 'unknown', programId: PUMPFUN_BONDING_CURVE_PROGRAM_ID, reason: 'no-invoke' };
    }
    const dataPayload = chunk.dataPayloads[0];
    if (!dataPayload) {
      return { kind: 'unknown', programId: PUMPFUN_BONDING_CURVE_PROGRAM_ID, reason: 'no-data-payload' };
    }
    const disc = dataPayload.slice(0, 8); // 8-byte Anchor event discriminator
    const payload = dataPayload.slice(8);
    switch (hexlify(disc)) {
      case EVENT_DISCRIMINATORS.create: return decodeCreate(chunk, payload);
      case EVENT_DISCRIMINATORS.trade:  return decodeTrade(chunk, payload);
      // ... remaining variants
      default:
        return { kind: 'unknown', programId: PUMPFUN_BONDING_CURVE_PROGRAM_ID, reason: `unknown-discriminator:${hexlify(disc)}` };
    }
  },
};
```

Event variants (bonding curve):

| Variant | `.kind` | Typed payload |
|---|---|---|
| Create | `pumpfun.create` | `{ mint, name, symbol, uri, creator, initialVirtualSolReserves, initialVirtualTokenReserves, timestamp }` |
| Trade | `pumpfun.trade` | `{ mint, solAmount, tokenAmount, isBuy, user, timestamp, virtualSolReserves, virtualTokenReserves, realSolReserves, realTokenReserves }` |
| Complete | `pumpfun.complete` | `{ mint, user, bondingCurve, timestamp }` |
| SetParams | `pumpfun.set_params` | `{ feeRecipient, initialVirtualTokenReserves, initialVirtualSolReserves, initialRealTokenReserves, tokenTotalSupply, feeBasisPoints }` |
| CreatorFee | `pumpfun.creator_fee` | `{ mint, creator, solAmount, timestamp }` |
| Migrate | `pumpfun.migrate` | `{ mint, bondingCurve, pool, timestamp }` |

Event variants (PumpSwap):

| Variant | `.kind` | Typed payload |
|---|---|---|
| Swap | `pumpfun.swap` | `{ pool, user, inputMint, outputMint, inputAmount, outputAmount, poolReserves, timestamp }` |
| AddLiquidity | `pumpfun.add_liquidity` | `{ pool, user, baseAmount, quoteAmount, lpTokens, timestamp }` |
| RemoveLiquidity | `pumpfun.remove_liquidity` | `{ pool, user, baseAmount, quoteAmount, lpTokens, timestamp }` |
| Admin | `pumpfun.admin_*` | variant-specific; each `.kind` gets its own suffix |

All payloads include the inherited signal metadata (slot, blockTime, signature) as added by the `EventDecoderRegistry.walk()` traversal — the decoder itself only produces the payload.

### 4.2 `pumpfun-protocol` — typed read-only client

**`curveState(rpcPool, mint)`** — fetches the bonding curve PDA account via `RpcPool.call('getAccountInfo', [curvePda, { encoding: 'base64' }])`, decodes the Anchor account layout, returns:

```ts
interface CurveState {
  mint: PublicKey;
  bondingCurve: PublicKey;         // the PDA itself
  virtualSolReserves: bigint;
  virtualTokenReserves: bigint;
  realSolReserves: bigint;
  realTokenReserves: bigint;
  tokenTotalSupply: bigint;
  complete: boolean;               // true iff the curve graduated to PumpSwap
  creator: PublicKey;
  createdAt: number;               // unix seconds, from the on-chain field
}
```

**`pumpSwapPoolState(rpcPool, pool)`** — similar, for the PumpSwap AMM pool account:

```ts
interface PumpSwapPoolState {
  pool: PublicKey;
  baseMint: PublicKey;
  quoteMint: PublicKey;
  baseReserves: bigint;
  quoteReserves: bigint;
  lpMint: PublicKey;
  feeBasisPoints: number;
  authorities: { freeze?: PublicKey; update?: PublicKey };
}
```

**`metadata(rpcPool, resolver, mint)`** — compose:
1. Derive the Metaplex metadata PDA via `@ap3x/solana-metaplex`'s PDA helper.
2. `rpcPool.call('getAccountInfo', [metadataPda])`.
3. Decode the on-chain metadata struct (name, symbol, URI, creators).
4. `resolver.resolve(uri)` to fetch the off-chain JSON (cached).
5. Return `{ onChain: ParsedMetadata, offChain: ResolvedMetadata }`.

**`holders(rpcPool, mint, limit)`** — thin wrapper over `@ap3x/solana-spl.getTokenLargestAccounts(rpcPool, mint)` when `limit ≤ 20`, falling back to `getTokenAccountsByMint` when `limit > 20`. Returns `HolderSummary[]` with `{ address, balance, pctOfSupply }`.

**`creator(rpcPool, mint)`** — convenience: `(await curveState(rpcPool, mint)).creator`.

**`fetchRecentTrades(rpcPool, mint, window)`** — stateless RPC helper:
1. Derive the bonding curve PDA for the mint.
2. `rpcPool.call('getSignaturesForAddress', [curvePda, { limit: window.limit, until: window.untilSignature }])`.
3. For each signature, `rpcPool.call('getTransaction', [sig, { maxSupportedTransactionVersion: 0 }])`.
4. Parse each tx's logs via `@ap3x/solana-events.parseLogs()`.
5. Run each chunk through `bondingCurveDecoder.decode()` + `pumpSwapDecoder.decode()`.
6. Filter to `pumpfun.trade` + `pumpfun.swap` variants for this mint.
7. Return typed `TradeEvent[]`.

No standing subscription. No caching. One call → one answer.

    // [signer] creator (writable)
    // [writable] mint
    // [writable] mintAuthority (PDA)
    // [writable] bondingCurve (PDA)

    // [] associatedTokenProgram

### 4.6 `pumpfun-protocol` — routing

```ts
export async function buy(
  rpcPool: RpcPool,
  mint: PublicKey,
  params: { user: PublicKey; solIn: bigint; maxSolCost: bigint; userTokenAccount: PublicKey }
): Promise<Instruction> {
  const curve = await curveState(rpcPool, mint);
  if (!curve.complete) {
    return buildBuy({ mint, ...params });
  }
  // post-graduation: find the PumpSwap pool for this mint
  const pool = await findPumpSwapPool(rpcPool, mint);
  // ... compute minOutputAmount from the caller's maxSolCost semantics
  return buildPumpSwapSwap({ pool, ... });
}

export async function sell(...) { /* symmetric */ }
```

`findPumpSwapPool(rpcPool, mint)` is a PDA derivation (one-shot, no RPC call — the pool address is deterministic from the mint per PumpSwap's design).

## 6. Error handling

**Decoder errors** return `UnknownEventDecode { kind: 'unknown', programId, reason }` with structured `reason`:
- `'no-invoke'` — chunk had no `Program <id> invoke` line (shouldn't happen in practice)
- `'no-data-payload'` — chunk had no `Program data:` line carrying the Anchor event
- `'unknown-discriminator:<hex>'` — 8-byte discriminator didn't match any known variant (cosmetic: program upgraded and added a new event type)
- `'truncated-data'` — Borsh decode failed on length
- `'borsh-parse-error:<field>'` — specific field failed to decode; the offending field name is in the reason string

Never throws. Never silently drops.

**Account decoders** fail closed with typed errors:
- `AccountLayoutError { expected: 'bonding-curve' | 'pumpswap-pool', observed: Uint8Array, field: string }`
- `AccountOwnerMismatch { expected: PublicKey, observed: PublicKey }`
- `AccountSizeError { expected: number, observed: number }`

**Instruction builders** validate at call time (not at simulate time):
- Negative amounts → `TypeError`
- `slippage > 10000 bps` → `TypeError`
- PDA derivation failures → propagate from `@ap3x/solana-core` derivations as-is
- `buildBuy` called on a mint whose curve has graduated (only surfaces if the caller uses the raw builder rather than `routing.buy`) → `CurveStateMismatch` with `{ mint, expectedState: 'active', observedState: 'complete' }`

**RPC / network errors** propagate from `@ap3x/solana-connectivity`'s `RpcPool` unchanged. The protocol package does not retry — the pool already has its own circuit breakers. One layer of retries, one layer of backoff.

**Never:** swallow errors, fill defaults for missing fields, retry-on-parse-error, throw inside decoders.

## 10. Risks + open questions

| Risk / question | Mitigation / plan |
|---|---|
| Pump.fun program upgrade breaks decoders | Nightly diag CI step decodes a fresh mainnet sample; `UnknownEventDecode` ratio above threshold triggers alarm. Tolerant decoders surface unknowns via the typed channel instead of throwing |
| PumpSwap pool account layout drift | Same pattern: account decoders emit `AccountLayoutError` on layout mismatch; diag probes nightly |
| Curve / AMM math off-by-one errors | ≥200-trade regression suite gate; live sanity checks during dogfooding |
| Instruction builders drift from on-chain program expectations | Roundtrip acceptance gate: builder output is simulated against devnet/mainnet fork and the resulting event is decoded back. Any layout or encoding drift surfaces immediately |
| Decoder registry conflicts when multiple verticals register against same program | Shouldn't happen (verticals own distinct programs); substrate's `EventDecoderRegistry.register` asserts no double-registration |
| Helius free tier rate limits during fixture capture | Capture scripts are one-shot, manually invoked. Can run overnight if needed; not on the CI hot path |
| Anchor event discriminator assumptions may differ between programs | Bonding curve is known Anchor; PumpSwap to be confirmed during Phase A. If PumpSwap uses a different event signaling convention (e.g., non-Anchor log parsing), the PumpSwap decoder adapts accordingly. Does not block the bonding curve work |
| Missing Helius API key at fixture-capture time | Both capture scripts self-skip; gate tests tolerate absent fixtures (skip with reason); CI remains green. Commit the fixtures to the repo once captured so subsequent runs have them |
