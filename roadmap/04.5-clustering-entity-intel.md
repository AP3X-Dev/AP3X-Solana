# PRP-04.5 — Clustering + entity intelligence

**Repo:** `ap3x-solana/` (continues from PRP-04)
**Depends on:** PRP-04 (event store + base/derived signals)
**Unblocks:** PRP-05 (extraction candidate: `@ap3x/clustering-core`), PRP-08 (strategies get rug-aware filtering for free)
**Estimate:** 3 weeks solo
**Master spec:** [00-master-platform-prp.md §6.4, §8](./00-master-platform-prp.md)

## Goal

Build wallet-graph clustering, role-based entity labeling, fund-flow tracing, and composite rug scorecard signals. **Replicates and exceeds what Bubblemaps, Arkham, Chainalysis, and Nansen do for pump.fun** — delivered as signals every strategy can query for safety, pre-buy research, and real-time risk monitoring.

The positioning matters: this is the opposite face of PRP-03.6's multi-wallet OpSec. PRP-03.6 gave operators tools to manage their own wallets; PRP-04.5 gives every strategy the intelligence to understand **other people's** wallets — who's a dev, who's a sniper cluster, who's an insider, which mints have coordinated holder groups, which devs have rug history. This is pure green — compliance-grade, regulator-friendly, retail-loved. It turns every strategy in the system into a safer one because every strategy gets clustering as a free input.

## In scope

### Package `@ap3x/pumpfun-clustering` (new)

- **Transfer-graph clustering** — union-find over direct transfers (SOL + tokens). Baseline cluster formation: wallets connected by at least one transfer within a configurable lookback are grouped. O(n·α(n)) complexity; scales to millions of wallets.
- **Common-funding clustering** — wallets with near-identical funding sources + timing. Heuristic: shared funding address + transfer within a time window + amount correlation → cluster candidate. Confidence score as a function of match strength.
- **Behavioral clustering** — wallets with matching program-interaction fingerprints. Fingerprint: the sequence of unique program IDs a wallet has invoked, weighted by frequency, embedded in a low-dimensional vector. Wallets with cosine similarity above threshold + temporal overlap → cluster candidate.
- **CEX-withdrawal clustering** — wallets funded from the same CEX withdrawal address within a configurable time window. High-precision signal; this is how most bulk-wallet preppers get caught.
- **Bundle co-occurrence clustering** — wallets that appear together in Jito bundles with frequency above a threshold. Catches sniper groups and launch-buddy coordination.
- **Cluster storage** — cluster memberships written to Parquet (partitioned by `date`) with DuckDB hot index. Schema:
  ```
  wallet_clusters(
    cluster_id: UUID,
    wallet: String (base58),
    method: Enum<'transfer'|'common_funding'|'behavioral'|'cex_withdrawal'|'bundle_cooccurrence'>,
    confidence: Float,
    observed_at: Timestamp,
    asof: Timestamp
  )
  ```
- **Cluster merging** — when multiple methods agree a set of wallets belong together, memberships merge under a canonical `cluster_id`. Confidence combines multiplicatively. Audit trail preserves which method contributed which evidence.
- **Incremental updates** — clustering runs as a daily batch job (backfill) + hourly incremental (recent events). Recomputation is idempotent; stale entries superseded by slot.

### Package `@ap3x/pumpfun-entities` (new)

- **Entity label taxonomy** — role-based labels only. No identity labels.
  - `cex_deposit` — behavioral fingerprint matches CEX deposit address patterns
  - `cex_withdrawal` — identified via official exchange lists + behavioral confirmation
  - `bridge` — known bridge contracts + wallets
  - `dex_lp` — holds LP tokens across major DEXes
  - `dev` — created ≥1 pump.fun mint via Create instruction
  - `graduated_dev` — dev whose prior mint(s) graduated to PumpSwap
  - `rugger_history` — dev whose prior mints match rug behavioral signature (authority restore + LP removal + dump sequence)
  - `sniper` — buys within N blocks of token creation with high frequency
  - `kol` — wallets whose buys correlate with identified social signal activity (optional, requires external social data integration)
  - `smart_money` — wallets with top-N% historical P&L over trailing window
  - `insider` — wallets funded from dev cluster AND active before public mint announcement (if such signal available)
  - `mev_bot` — wallets with JIT liquidity or arb patterns
  - `washtrader_candidate` — wallets in a cluster whose trade volume is >X% internal to the cluster
  - `honeypot_deployer` — contract creators whose tokens have blacklist / freeze authority used maliciously (post-hoc label)
  - `mixer_adjacent` — wallets that have interacted with known mixing services (compliance flag)
- **Labeling pipeline** — daily batch job + on-demand recomputation. Each label has:
  - `source`: `heuristic` | `community` | `behavioral` | `external_feed`
  - `confidence`: 0.0-1.0
  - `evidence`: structured record of what triggered the label
  - `version`: label computation version pin
- **Label storage** — Parquet, DuckDB hot index:
  ```
  entity_labels(
    target_id: UUID or String (cluster_id or wallet),
    label: String,
    source: Enum,
    confidence: Float,
    evidence: JSON,
    label_version: String,
    observed_at: Timestamp,
    asof: Timestamp
  )
  ```
- **Label inheritance** — labels attach to clusters first. A wallet's effective labels = union(direct labels on wallet, labels on clusters the wallet belongs to). Confidence combines via documented formula (weighted max of direct + inherited).
- **Dispute / override mechanism** (forward-looking, stub in v1) — operator-controlled label corrections. An interface for overriding a label with attribution; actual dispute-resolution workflow is PRP-05+ territory.

### Package `@ap3x/pumpfun-signals` additions

- **`getClusters(mint, asOf)`** — returns cluster breakdown of the mint's current holders. Includes:
  - Top N clusters by holding %
  - Per-cluster labels + confidence
  - Cluster size (wallet count)
  - Cluster's aggregate position in this mint
  - Pluggable format: table (for CLI) or graph (for visualization)
- **`getEntityLabels(wallet_or_cluster, asOf)`** — all labels for a target with confidence + evidence. Time-indexed via `asOf`.
- **`getFundFlow(wallet, asOf, direction, depth)`** — recursive upstream / downstream trace:
  - `direction: 'upstream' | 'downstream'`
  - `depth: number` (max hops)
  - Returns a DAG of `(from, to, amount, token, slot)` edges, terminating at CEX deposits / bridges / unknown-origin wallets
  - Time-indexed (all edges ≤ `asOf`)
- **`getRugScorecard(mint, asOf)`** — composite safety scorecard. Factors:
  - `devReputation` (PRP-04) — dev cluster's track record
  - `topClusterConcentration` — aggregate % held by top 5 clusters
  - `sniperClusterExposure` — % held by wallets labeled `sniper`
  - `insiderClusterExposure` — % held by wallets labeled `insider`
  - `authorityStatus` — mint / freeze / update authority states
  - `liquiditySafety` — LP lock status, burn status, dev LP holdings
  - `behavioralAnomalies` — recent unusual patterns (sudden concentration shift, authority restoration, etc.)
  - Output: `{ score: 0-100, grade: 'A'-'F', factors: [{ name, score, weight, explanation }], version }`
- **`getClusterConcentration(mint, asOf)`** — distribution metrics:
  - Top 5 / 10 / 20 clusters hold %
  - Herfindahl-Hirschman Index
  - Entropy
  - Fresh-wallet concentration (wallets <24h old)
- **Real-time monitoring signals** (streaming, fires via PRP-02 SignalQueue):
  - `clusterMovement(mint)` — fires when a labeled cluster's position changes significantly (threshold-configurable)
  - `authorityChange(mint)` — fires when mint / freeze / update authority modified
  - `liquidityChange(mint)` — fires when LP added / removed / unlocked
  - `fundFlowAlert(watched_cluster)` — fires when a watched cluster moves funds toward CEX deposits (pre-sell signal)

### Integration with PRP-04's event store

- No schema changes to event store — clustering and labeling derive from existing events.
- Precomputed cluster/label tables sit alongside the event store Parquet; queries JOIN dynamically.
- `asOf` enforcement is inherited from PRP-04's query layer; all cluster and label queries filter by `observed_at <= asOf`. CI fuzz test from PRP-04 extended to cover these new tables.

### Integration with PRP-03's policy engine

- New `getRugScorecard` tool schema — Tier 0 (read-only). Available to all strategies.
- Policy engine gains `require_rug_scorecard: { min_score: number }` as a per-strategy configuration. Strategies below the threshold on the target mint auto-reject writes. Enforced at tool layer; strategies cannot override inline.

## Out of scope

- **Real-world identity labels** — no "this is John Doe" ever. Platform ships role labels only. Categorically not a feature, not a future work item.
- **Public dashboard / search UI** — API-first. Strategies consume clustering signals; operators query via CLI. No public-facing search tool (avoids becoming a doxx destination à la Arkham's public search).
- **Purchased / leaked real-world-identity data integration** — categorically excluded.
- **Cross-chain wallet linking** — Solana-only for PRP-04.5. Hyperliquid cluster linking is PRP-07+ scope.
- **Learned-model clustering** — v1 is deterministic heuristics. v2 (gradient-boosted or embedding-based learned models) is PRP-08+ scope when there's enough labeled data to train against.
- **Real-time clustering** (sub-minute) — v1 is batch daily + hourly incremental. Real-time cluster recomputation is premature optimization.
- **Social media integration for KOL labeling** — `kol` label can exist with heuristic detection (wallets whose buys precede price movements on specific mints); integrating actual social signal data is optional future work.
- **Automated rug prediction** — the rug scorecard is a composite signal with explicit factors, not a black-box predictor. No "AI said this will rug" output.

## Acceptance criteria (gate)

1. **Baseline clustering F1 ≥ 85%** on a hand-labeled holdout set of 50 known wallet groups (mix of CEX deposits, sniper bots, dev cluster + buddy wallets, legitimate independent traders).
2. **Rug scorecard precision ≥ 70%** on a holdout set of 100 rugged tokens (tokens that lost >90% value within 7 days of peak from dev actions). Recall ≥ 60%. Measured via operator review.
3. **Cluster query performance** — p95 of `getClusters + getClusterConcentration` composite < 250ms on 30-day event store. `getFundFlow(depth=3)` p95 < 500ms.
4. **Zero identity labels** — static analysis of `@ap3x/pumpfun-entities` confirms no label in the taxonomy references a person / handle / username. Integration test verifies labeling pipeline cannot emit identity labels (no code path exists).
5. **Signal version pinning** — `cluster_version`, `label_version`, `scorecard_version` pinned per query result. Backtests pinning v1 produce identical outputs across runs. CI regression test.
6. **As-of enforcement** — fuzz test 10,000 randomized queries; zero leaks of post-`asOf` cluster memberships or label entries.
7. **Real-time monitoring latency** — cluster movement / authority change / liquidity change alerts fire within 5 slots (≈2 seconds on mainnet) of the triggering event.
8. **Wallet tagging recall** — known dev wallets tagged `dev` with ≥95% recall; known KOL wallets tagged correctly ≥80%; known sniper bots tagged ≥90% (holdout sets operator-curated).

## Key design decisions

- **Role labels, not identity labels.** Non-negotiable. `sniper_cluster_#423`, not "Bob's sniper bots." Keeps us out of the Arkham backlash territory + out of doxxing-platform territory + legally defensible.
- **API-first, not public UI.** Capability for strategies, not a doxx destination. Operators query via CLI; strategies consume programmatically. If a consumer product wants to surface scorecards publicly, it's that product's decision, not the platform's.
- **Clusters are first-class; labels attach to clusters.** A label on "sniper_cluster_#423" applies to every wallet in the cluster. This is what makes coordinated groups legible without re-deriving per wallet.
- **All cluster snapshots time-indexed.** Inherits PRP-04's as-of semantics. Strategies can't silently benefit from post-hoc clustering improvements — version + asOf pin everything.
- **Heuristic v1 before learned v2.** Explainable + auditable. Operators can inspect what triggered a label. Learned models layer on top later when training data is sufficient.
- **Daily batch + hourly incremental, not real-time clustering.** Correct defaults matter more than freshness for most use cases. Real-time monitoring signals handle the freshness-sensitive cases (authority changes, liquidity changes, cluster movement) without requiring full cluster recomputation.
- **Build pump.fun-specific first, extract in PRP-05.** Matches roadmap principle: resist premature abstraction. The clustering framework extracts cleanly (algorithms + storage + API); the label taxonomy stays pump.fun-specific until a second vertical forces cross-vertical generalization.
- **No rug prediction as an oracle.** Scorecard is a composite with explicit factors, not a black-box verdict. Operators see what drove a score and can override weighting for their strategy.

## Risks + open questions

| Risk | Mitigation |
|---|---|
| Clustering false positives damage wallet reputations | Conservative confidence thresholds; labels are advisory not blocking for policy; confidence always surfaced with the label; dispute mechanism forward-looking; operator override capability exists |
| Rugger history labels legally disputable (calling someone a "rugger" could be defamation) | Label text is `rugger_history` (behavioral pattern) not `rugger` (identity claim). Evidence record is explicit: "this wallet cluster created N mints with pattern X." Provides factual basis for every label. |
| Storage cost at scale | Partition by date, cold-tier older clusters to object storage, precomputed hot window of 30-60 days locally queryable |
| DuckDB query performance degrades past 1yr of data | Precomputed cluster caches at `(mint, asof_bucket=5min)` granularity; escalate to ClickHouse if needed post-GA |
| Heuristic clustering misses sophisticated obfuscation | Acknowledged explicitly in docs; v2 learned models address when data allows; confidence scores reflect uncertainty; operators shouldn't rely on clustering alone for high-stakes decisions |
| Behavioral fingerprinting catches false positives (independent traders with similar patterns) | Multi-method consensus required for high-confidence clusters (transfer + common_funding + behavioral agreeing); single-method behavioral clusters carry low confidence by default |
| Rug scorecard over-promises in marketing | Explicit probabilistic framing in docs: "composite risk indicator, not a rug predictor." Always displayed with factor breakdown so users see what drove the score |
| KOL label fails gracefully without social data integration | `kol` label is optional in v1; heuristic detection (temporal correlation with price movements) works standalone; social feed integration is incremental upgrade |

## Platform extraction to PRP-05

The framework extracts cleanly to cross-vertical packages:

- **`@ap3x/clustering-core`** — clustering algorithms (union-find, behavioral fingerprinting, CEX-withdrawal detection, bundle co-occurrence), storage schemas, query API. Vertical-agnostic.
- **`@ap3x/entity-framework`** — label taxonomy interface, evidence schema, confidence math, dispute/override hooks. Taxonomy instances (pump.fun labels, Hyperliquid labels, etc.) stay in vertical packages.
- **`@ap3x/signals-core`** (already planned in PRP-05) — absorbs `getRugScorecard`-shaped composite signal pattern as a generic capability: "compose N signals into a graded score with factor breakdown."

Clustering is inherently cross-vertical. Hyperliquid has wallets; they cluster. Polymarket has wallets; they cluster. The framework this PRP builds will be a first-class platform capability from PRP-05 onward.

## Positioning statement (for docs)

**What this is:** on-chain intelligence infrastructure. Replicates the capabilities of Bubblemaps, Arkham, and Chainalysis for pump.fun, integrated as signals every strategy can query.

**Who it's for:** every strategy in the platform benefits automatically. Traders who want pre-buy safety warnings. Compliance-aware operators. Researchers studying on-chain behavior. Retail users want the rug scorecard before they click buy.

**What it isn't:** not a doxxing tool. Not a public search engine. Not an identity-linking service. Role labels (behavior, not identity); API-first (strategies, not casual lookup); composable signals (strategy building block, not end-user surveillance).
