# PRP-01.5 — Solana webhook ingestion

**Repo:** `ap3x-solana/` (peer concern to PRP-01)
**Depends on:** `@ap3x/solana-core`, `@ap3x/solana-events`, `@ap3x/solana-signals`
**Unblocks:** any vertical that wants webhook-based ingestion as an alternative or complement to Geyser (pump.fun, Raydium, downstream off-chain feeds)
**Estimate:** 1-2 weeks for the 0.1 alpha already in tree; further hardening folds into PRP-02/04 as their consumers force it.

## Status

**0.1 alpha shipped on `main` (2026-04-30).** `@ap3x/solana-webhooks` is published as a workspace package with the core ingestion path, an outbox-first persistence layer, the Helius driver, and a captured-fixture test suite (122 tests). The pieces below are described as shipped vs deferred, not as future work to scope from scratch.

## Goal

Add **webhooks as a peer transport to Geyser** for the substrate's event ingestion surface. Geyser is the live-stream path that PRP-01 ships; webhooks are a complementary path that some providers (Helius enhanced webhooks, off-chain notification feeds, internal event buses) expose more reliably than gRPC streams. Both produce the same `TypedSolanaEvent` records downstream — a vertical doesn't care which transport delivered them.

The headline property is **outbox-first persistence**: every payload that passes verification is durably stored before it's acknowledged, so a process crash between "received" and "handled" never loses an event. The drainer is the only component that interprets payloads; the receiver, outbox, and HTTP server are transport-agnostic.

## Shipped in 0.1 alpha

### Package `@ap3x/solana-webhooks`

- **HTTP receiver** — `createReceiverHandler` + `createWebhookServer` with HMAC-style auth (driver-specified header semantics), payload size cap, and bounded-concurrency backpressure (semaphore). Returns 4xx for verification failures, 5xx for outbox errors, 2xx + idempotent insert otherwise.
- **Outbox interface** — `Outbox` abstraction with `SqliteOutbox` (default; `better-sqlite3` peer dep) and `PostgresOutbox` (`pg` peer dep) implementations. Cross-backend parity suite locks the two implementations to the same observable behaviour.
- **Drainer** — pulls pending rows from the outbox, hands the parsed payload to the configured driver's `normalizeEvent`, emits one or more `TypedSolanaEvent`s per row, and marks the row delivered. At-least-once semantics; idempotency keys are the driver's responsibility.
- **Healthz probe** — `Healthz` returns liveness + last-success timestamps so an external watchdog can detect a stuck pipeline (`DEFAULT_SILENT_THRESHOLD_MS` configurable).
- **Helius driver** — first concrete `WebhookDriver`. Handles the enhanced-webhook envelope (JSON array of enhanced txs), verifies the shared-secret `Authorization` header (constant-time compared, raw secret — confirmed against the upstream Python tracker source), parses per-tx, normalises into the substrate's typed event union, exposes catchup (`HeliusCatchup`) and admin (`HeliusAdmin`) sub-clients backed by Helius's REST endpoints. Per-tx idempotency key is `helius:<signature>`. Outbox stores per-tx parsed JSON, not the raw wire body, so re-drain reproduces deterministic events without a wire-format dependency.
- **Captured-fixture suite** — eight named fixtures + two batch-shape fixtures cover SWAP buy / sell, Jupiter multi-hop, pump.fun bonding-curve buy, TOKEN_MINT buy, dust-rebate edge case, plain transfer, failed tx, multi-wallet swap. Suite drives the receiver, drainer, and normalizer end-to-end.
- **Replay-parity gate** — TypeScript `classifyHeliusBuy` projection vs the Python reference parser (`gmgn_tracker.helius.parser.parse_buy`) compared cell-by-cell across all named fixtures. Threshold ≥95% byte parity; current run is 100% (33/33 cells). Self-skips when Python or the tracker package isn't on the developer's machine, so CI runs honor the local layout.

### CI

- `webhooks-postgres-tests` matrix on PG 14 / 15 / 16 runs the cross-backend parity suite against real Postgres (sqlite path is exercised on every push).

### Examples

- `examples/solana-watch --webhook <fixture.json>` — peer mode to the existing Geyser flow. Reads a captured Helius enhanced-tx payload (single-tx or array shape), runs `normalizeHeliusTx`, and emits one JSON line per typed event with `{slot, programId, kind, latencyMs}`. Mirrors the Geyser-mode line schema so a downstream consumer sees one stream regardless of transport.

## Deferred to later PRPs

- **Additional drivers** — Triton webhooks, QuickNode webhooks, custom internal feeds. Each adds a `WebhookDriver` implementation; the receiver/outbox/drainer don't change.
- **Ordered drain** — current drainer is FIFO per-row but does not enforce ordering across rows. Pump.fun's signal layer (PRP-04) is the first consumer that may need stricter ordering; revisit there.
- **Retry policy + DLQ** — `OutboxRow` carries an attempt counter today but rows that exceed it stay marked failed. A dead-letter queue + alerting hook lands when a real consumer needs it.
- **Backpressure metrics** — `MetricsEmitter` ships as a `noopMetrics` interface today. Wire to a real metrics sink (Prometheus, OTel) when Chad's PRP-12 rebuild lands and the platform exposes metrics surface.
- **Retention + replay tooling** — outbox grows monotonically. Trim policy + replay-from-cursor utilities ride PRP-04's event-store work.

## Acceptance criteria (gate, retroactive)

1. Receiver accepts HMAC-verified payloads under `DEFAULT_MAX_BYTES`, rejects oversize / unauthenticated, and refuses past `DEFAULT_MAX_CONCURRENT` in flight.
2. SQLite + Postgres outboxes pass the cross-backend parity suite identically.
3. Drainer marks rows delivered atomically with the consumer's emit callback succeeding; replay after crash mid-emit produces the same `TypedSolanaEvent`s on re-drain.
4. Helius driver normalises every captured fixture into a non-empty event stream — substrate's "never silently drop" rule holds.
5. Replay-parity ≥95% across all named BUY-classification fixtures; current run is 100%.
6. CI green on the postgres matrix (PG 14 / 15 / 16) + the default sqlite path.
7. Zero runtime deps outside the substrate (`@ap3x/solana-core`, `-events`, `-signals`, `-connectivity`). Peer deps for outbox storage (`better-sqlite3`, `pg`) are optional.

## Key design decisions

- **Outbox-first, not best-effort.** A receiver that returns 200 before persisting is one crash away from silent data loss. The outbox lives between receive and handle so the driver's normalize logic can be retried, hot-swapped, or replayed without re-fetching from upstream.
- **Driver-shaped, not Helius-shaped.** Helius is the first driver but the abstraction is `WebhookDriver`. Anything that posts to an HTTP endpoint with a verifiable signature can plug in without touching the receiver, outbox, or drainer.
- **Substrate-shape downstream.** Drivers normalize into `TypedSolanaEvent`, not driver-specific payloads. Consumers (signal layer, strategy runtime, examples) bind to the substrate shape; if Helius rotates a field, only the driver's normalize function changes.
- **Test against real captures.** The fixture set is captured wire payloads, not synthesised. The replay-parity suite compares against an external reference parser (Python) so the TS implementation can't silently drift away from upstream truth.
- **Outbox stores parsed payloads.** Per-tx JSON, not the raw wire body. Replay produces the same events even if Helius's batching shape rotates; the cost is one parse-on-receive instead of parse-on-replay.

## Risks + open questions

| Risk | Mitigation |
|---|---|
| Helius rotates the auth scheme (HMAC-of-body instead of raw secret) | Driver `verifyRequest` is the single point of change; constant-time comparison stays. |
| Outbox grows unbounded in long-running deployments | Trim/retention deferred to PRP-04 where the event store ships its own retention; until then, run periodic vacuum out-of-band. |
| At-least-once delivery surfaces double-counted events to naive consumers | Per-tx idempotency keys (`helius:<signature>`) in the typed event stream; consumers are expected to dedup on those. PRP-04's event store enforces this at storage. |
| Postgres-specific syntax drifts from sqlite | Cross-backend parity suite catches it; matrix CI exercises both. |
