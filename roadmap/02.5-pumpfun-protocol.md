# PRP-02.5 — Pump.fun vertical, Phase 0: Protocol + instruction builders + typed read-only client

**Repo:** `ap3x-solana/` (same monorepo; substrate + runtime + pump.fun vertical coexist)
**Depends on:** PRP-01 (Solana substrate), PRP-02 (Solana runtime)
**Unblocks:** PRP-03 (execution + safety)
**Estimate:** 2-3 weeks solo
**Master spec:** [00-master-platform-prp.md §5.1, §6.3](./00-master-platform-prp.md) (Layer 3 of the 10-layer architecture)

**History:** originally numbered PRP-02. When PRP-02 was redefined as the Solana runtime (signals → strategy → executor → portfolio), this pump.fun protocol work was re-sequenced to PRP-02.5 so it sits cleanly between the runtime and the execution-safety PRP that consumes its instruction builders and curve math.

## Goal

First Solana vertical on the platform. Ship **`@ap3x/pumpfun-protocol`** + **`@ap3x/pumpfun-events`** — pump.fun program decoders, bonding curve + PumpSwap AMM math, typed read-only client, and pure instruction builders for the full on-chain surface (buy, sell, create, swap) — entirely on top of `@ap3x/solana-*`. At the end of PRP-02.5 a developer can observe every pump.fun on-chain event with full typing, query any mint's state, compute fair prices on either side of the graduation boundary, and **construct any pump.fun instruction** ready to be signed and submitted.

PRP-02.5 stops short of the write-path safety layer (simulate, receipt, policy, Jito dispatcher). That ships in PRP-03 and wraps these builders.

This PRP is the first real test of `@ap3x/solana-*` as a foundation (now including the runtime). Most of the work is leverage — the substrate handles connectivity, tx assembly, SPL, Metaplex, event framework, and keys; the runtime owns signal routing, strategy dispatch, execution plumbing, and portfolio. Pump.fun only needs its program-specific protocol code.

## In scope

### Package `@ap3x/pumpfun-events`

Lower-level: program ID constants + decoders plugged into the substrate's `EventDecoderRegistry`.

- **Program IDs** — `PUMPFUN_BONDING_CURVE_PROGRAM_ID`, `PUMPFUN_PUMPSWAP_PROGRAM_ID` exported as `PublicKey` constants.
- **Bonding curve program decoder** — one `ProgramDecoder<PumpFunBondingCurveEvent>` returning a discriminated union:
  - `CreateEvent` — new token mint on the bonding curve
  - `TradeEvent` — buy + sell on the bonding curve
  - `CompleteEvent` — bonding curve hits graduation threshold
  - `SetParamsEvent` — admin parameter change
  - `CreatorFeeEvent` — creator-fee payout
  - `MigrateEvent` — transition to PumpSwap (signals graduation)
- **PumpSwap AMM decoder** — one `ProgramDecoder<PumpSwapEvent>` returning a discriminated union:
  - `SwapEvent` — post-graduation buy/sell on the AMM pool
  - `AddLiquidityEvent`
  - `RemoveLiquidityEvent`
  - `AdminEvent` — any pool-admin variants observed
- **Kind namespace** — `pumpfun.create`, `pumpfun.trade`, `pumpfun.complete`, `pumpfun.set_params`, `pumpfun.creator_fee`, `pumpfun.migrate`, `pumpfun.swap`, `pumpfun.add_liquidity`, `pumpfun.remove_liquidity`, `pumpfun.admin_*`.
- **Typed event unions** — exhaustive match enforced at the type level; unknown variants surface via the substrate's `UnknownEventDecode` channel (no silent drops).
- **Slot + timestamp + signature** attached to every decoded event.
- **Stateless** — no lifecycle, no background tasks. Decoders are pure `(ProgramLogChunk) → Event | UnknownEventDecode` functions.

### Package `@ap3x/pumpfun-protocol`

Higher-level: typed read-only client, pure math, pure instruction builders.

- **Typed read-only on-chain client** (stateless; all methods are one-shot RPC calls):
  - `curveState(mint)` — reads the bonding curve account directly via `@ap3x/solana-connectivity` RPC; returns typed record (virtual_sol_reserves, virtual_token_reserves, real_sol_reserves, real_token_reserves, complete, creator, created_at)
  - `pumpSwapPoolState(pool)` — reads the PumpSwap AMM pool account; typed reserves + LP mint + authorities
  - `metadata(mint)` — composes Metaplex on-chain metadata decode + `MetadataResolver.resolve(uri)` from `@ap3x/solana-metaplex`
  - `holders(mint, limit)` — wraps `@ap3x/solana-spl`'s `getTokenLargestAccounts` / `getTokenAccountsByMint`
  - `creator(mint)` — derived from `curveState`
  - `fetchRecentTrades(rpcPool, mint, window)` — stateless RPC helper: `getSignaturesForAddress` + `getTransaction` + decode via `@ap3x/pumpfun-events`. One-shot, no background subscription. (Live streaming is the runtime's `SignalQueue` responsibility, not this package's.)
- **Bonding curve math** — pure BigInt functions, unit-tested against on-chain observed trades:
  - `priceFromReserves(reserves)`
  - `tokensOutForSolIn(solIn, reserves)` — matches on-chain program output within 1 bps
  - `solOutForTokensIn(tokensIn, reserves)`
  - `pctToGraduation(reserves)`
  - `priceImpactBps(size, reserves)`
- **PumpSwap AMM math** — pure BigInt functions for the constant-product pool (tokens continue to trade after graduation; strategies tracking positions across the boundary need this):
  - `ammPrice(reserves)`
  - `ammTokensOut(solIn, reserves)`
  - `ammSolOut(tokensIn, reserves)`
- **Pure instruction builders** — return `{ programId, accounts, data }` tuples compatible with `@ap3x/solana-tx`. Do not sign, do not submit. Pure functions of their inputs. Typed params per instruction.
  - `buildCreate(params: CreateParams)` — mint a new pump.fun token
  - `buildBuy(params: BuyParams)` — bonding curve buy
  - `buildSell(params: SellParams)` — bonding curve sell
  - `buildPumpSwapSwap(params: PumpSwapSwapParams)` — post-graduation swap
  - **Not in scope here:** `buildMigrate` (migration is admin-triggered by the pump.fun program itself), `buildSetParams` (admin-only), authority-revocation builders (live in PRP-03.5 alongside their policy-tier-3 gating).
- **Typed params** — `CreateParams`, `BuyParams`, `SellParams`, `PumpSwapSwapParams` exported from the package's public API. Strategies and write-path code never touch raw account layouts or instruction-data bytes.
- **Unified routing** — `buy(mint, params)` / `sell(mint, params)` helpers that internally dispatch to `buildBuy` / `buildSell` when the token's still on the bonding curve, or `buildPumpSwapSwap` once `curveState.complete === true`. Callers work with one API across the graduation boundary.

### Example app `examples/pumpfun-watch/`

Mirrors `examples/spl-watcher/`'s pattern (CLI, source selection, e2e fixture replay test). Adds alongside `solana-watch` + `spl-watcher`, does not replace them.

- CLI with `--source fixture | historical | live` flags (fixture default in tests; live requires Helius API key)
- Subscribes to both pump.fun programs (bonding curve + PumpSwap) via Geyser
- Decodes all event variants with full typing
- Tracks curve state on all mints in the subscription window
- Prints typed stream to stdout with latency measurement
- Bundled replay fixture so `pnpm --filter examples/pumpfun-watch test` runs end-to-end without live deps

## Out of scope

- **Write-path safety layer** (simulate, receipt-gated submit, Jito bundle dispatcher, policy engine, tiers, circuit breakers, kill switch, audit log) → PRP-03
- **Authority revocation + metadata update builders** → PRP-03.5 (live alongside their Tier-3 irreversibility gating in the policy engine)
- **Vanity mint grinding, launch+snipe atomic bundles, airdrop distribution** → PRP-03.5
- **Pump.fun off-chain HTTP APIs** (`advanced-api-v2.pump.fun`, `frontend-api-v3.pump.fun`) → PRP-04. Treated as a first-class signal source feeding the event store, not as a standalone compat package. Gets the same persistence, time-indexing, and backtest semantics as on-chain data.
- **Event store, historical backfill as queryable archive, signal derivations** → PRP-04
- **Dev reputation / smart money / bundle detection / graduation ETA** → PRP-04
- **Backtest harness** → PRP-04

## Deliverables

1. Two packages built + tested in `ap3x-solana/`: `@ap3x/pumpfun-events`, `@ap3x/pumpfun-protocol`.
2. Pump.fun decoders registered with `@ap3x/solana-events` framework (both programs) — verified by the example app processing real events.
3. Instruction builders (`buildCreate`, `buildBuy`, `buildSell`, `buildPumpSwapSwap`) with roundtrip tests: build instruction → assemble tx via `@ap3x/solana-tx` → simulate via RPC → decode the simulation result → assert it matches the expected event shape.
4. `examples/pumpfun-watch/` running 1 hour continuous on live mainnet; printing every pump.fun event variant with typed records.
5. Bonding curve + AMM math regression suite with ≥ 200 real on-chain trades (≥100 bonding curve, ≥100 PumpSwap) matching observed fills within 1 bps.
6. Captured test fixtures committed under `tests/fixtures/`:
   - `pumpfun-per-variant.jsonl.gz` — ~100 events, one real sample per variant (decode correctness tests)
   - `pumpfun-lifecycle.jsonl.gz` — ~500 events, full lifecycle traces for 2-3 tokens from Create through PumpSwap trading (integration + graduation-boundary tests)
   - Capture scripts in `tests/helpers/capture/` following the PRP-02 pattern; Helius-free-tier-compatible
7. Documentation — READMEs + usage examples; `docs/architecture/pumpfun.md` explaining how the vertical sits on top of the substrate + runtime, including the graduation-boundary lifecycle.

## Acceptance criteria (gate)

1. **Live decoding** — `pumpfun-watch` example runs 1 hour continuous, receives every event variant across both programs, decodes with **p50 < 500ms, p99 < 2s** end-to-end lag.
2. **Per-variant decode correctness** — every variant decodes correctly against the per-variant fixture; one unit test per variant; integration test against the full-lifecycle fixture exercises the graduation boundary (bonding curve `CompleteEvent` → `MigrateEvent` → PumpSwap `SwapEvent` for the same token).
3. **Bonding curve + AMM math** — passes the regression suite of ≥ 200 real on-chain trades within 1 bps.
4. **Read client correctness** — `curveState(mint)` and `pumpSwapPoolState(pool)` return correct values for a sample of 10 live mints each, verified against raw on-chain account inspection.
5. **Instruction builder roundtrip** — for each builder, a test assembles a real tx from the builder output via `@ap3x/solana-tx`, simulates it on devnet (or against a mainnet fork), and asserts the resulting event decodes back to the same typed params the builder was called with.
6. **Zero ecosystem deps** — verified by CI forbidden-deps gate (same as PRP-01/02); no `@solana/web3.js`, `@solana/spl-token`, `@metaplex-foundation/*` in any pump.fun package's runtime `dependencies`.
7. **Zero modifications required to `@ap3x/solana-*` substrate or runtime packages** — verified by git diff + substrate/runtime test suites staying green.
8. **Unknown event variants decode to structured `UnknownEventDecode` records** (zero silent drops) — verified by feeding synthetic malformed logs.
9. **CI green on Ubuntu + Windows.**

## Key design decisions

- **Pump.fun as first validator of substrate + runtime, not their reason for being.** Substrate and runtime design decisions are re-evaluated only if pump.fun concretely can't implement something on top of them. Required modifications trigger an immediate refactor PRP on the affected layer.
- **On-chain data only. Off-chain data is a signal source, not a compat package.** Pump.fun's `advanced-api-v2` and `frontend-api-v3` HTTP surfaces are augmentation data (trending feeds, comment counts, creator social links) — not authoritative. They belong in PRP-04's signal layer where the event store gives them persistence, time-indexing, and backtest semantics alongside on-chain events. Consumer apps (including Chad when rebuilt in PRP-12) read both through the same signal-layer interface, not through a bespoke HTTP wrapper.
- **Instruction builders are pure functions and live here; safety is in the runtime.** Every substrate package that has instructions (`@ap3x/solana-spl`, `@ap3x/solana-metaplex`) ships its builders as pure `(params) → { programId, accounts, data }` functions. Pump.fun matches this pattern. Safety (simulate → receipt → policy-gated submit) is a separate concern that wraps the builder outputs, and that layer ships in PRP-03.
- **Stateless protocol package.** No lifecycle, no background tasks, no in-memory stream buffers. Live streaming is the runtime's `SignalQueue` responsibility; callers wanting live pump.fun trades subscribe to the queue filtering for `pumpfun.trade` / `pumpfun.swap` kinds. Historical backfill of older windows is PRP-04's event store. `@ap3x/pumpfun-protocol` is pure request/response — trivially testable, trivially composable.
- **Event decoders plug into substrate's registry.** Pump.fun decoders live in `@ap3x/pumpfun-events` but register with `@ap3x/solana-events`' framework. Other Solana verticals' decoders coexist without conflict.
- **PumpSwap math ships in PRP-02.5.** Post-graduation tokens live on PumpSwap, not on the bonding curve. Any strategy tracking a position across the graduation boundary needs AMM math to compute fair price and sizing post-grad. Deferring this to a later PRP would cripple strategies from day one.
- **Real captured fixtures over synthetic mocks.** Matches the user's stated preference. Per-variant fixtures give tight, fast decode unit tests; the full-lifecycle fixture exercises cross-event flow and the migration boundary where integration risk concentrates. Both fixtures captured via Helius free tier.

## Risks + open questions

| Risk | Mitigation |
|---|---|
| Pump.fun program upgrade breaks decoders | Nightly diag probes decode a fresh mainnet event sample; shape drift triggers alarm; tolerant schemas surface unknown variants via `UnknownEventDecode` instead of throwing |
| PumpSwap pool account layout drift | Same pattern: typed account decoders emit `UnknownEventDecode`-style structured errors on layout mismatch; diag probes the layout nightly |
| Curve / AMM math off-by-one errors | Regression suite gate; live sanity checks during dogfooding |
| Decoder registry conflicts when multiple Solana verticals register against same program | Shouldn't happen (verticals own distinct programs), but assertion in framework catches double-registration |
| Instruction builders drift from on-chain program expectations | Roundtrip acceptance gate: builder output is simulated against devnet/mainnet fork and the resulting event is decoded back. Any layout or encoding drift surfaces immediately. |
| Scope creep from "full on-chain surface" expanding further | Out-of-scope list is load-bearing; the line is explicit at admin/irreversible operations which live in PRP-03.5 |

## What PRP-02.5 proves

Two-to-three week shipment of a first vertical (decoders + math + read client + instruction builders) on top of the substrate + runtime validates the abstraction split. If PRP-02.5 takes 4+ weeks, the abstractions are wrong and should be revisited before proceeding to PRP-03.
